# TS-2026-003: Rekor anchoring never succeeded, and the unwitnessed-time gate trusted local records

| Field             | Value                                                        |
|-------------------|--------------------------------------------------------------|
| **Identifier**    | TS-2026-003                                                  |
| **Title**         | The hub's Rekor submissions were always rejected and the failure was hidden; `verify --max-unwitnessed` took witness times and claimed times from unsigned local records, and ran only in the default text output |
| **Affected**      | `treeship` CLI and `treeship-core` `<= 0.31.8` (`verify --max-unwitnessed`, `hub push`); the treeship.dev hub through the same date |
| **Fixed in**      | `0.31.9`                                                      |
| **Severity**      | Medium. A false pass in an opt-in policy check, local to the verifying machine. No counterparty-facing artifact carried a forged anchor, because packages and bundles carried no anchors at all |
| **Discovered by** | Outside design review and internal code check, 2026-09-23/24 |
| **Public disclosure window** | None. Fix ships in the next release. No field exploitation observed |

## Summary

Treeship's time-anchoring story rests on an outside witness: a record,
held by someone other than the operator, that a receipt existed at a
given time. Two things were wrong with it.

**Rekor anchoring never worked.** The hub submitted each pushed artifact to
the public Rekor log as a `hashedrekord` entry. Every submission was
rejected. Treeship signatures are unpadded base64url, and Rekor decodes
that field as padded standard base64. Fixing the encoding alone would not
have helped either, because `hashedrekord` verifies Ed25519 only in its
pre-hashed variant, and Treeship signs plain Ed25519 over the DSSE PAE
bytes. The hub logged the rejection and returned success without a log
index. The CLI printed `rekor: pending`. The production hub's logs from
2026-09-16 onward show only rejections, and no local store we checked
holds a Rekor index.

**The gate trusted the operator's own files.** `verify --max-unwitnessed`
exists to fail a chain whose timeline nobody outside the machine
witnessed. It computed coverage from two unsigned values in the local
store:

1. An anchor's time was `Record.anchors[].observed_at`, written by the
   pushing machine's clock into a file the operator controls. Adding
   anchors with chosen times to a record made an eight-hour unwitnessed
   chain pass a one-hour policy.
2. The claimed timeline came from `Record.signed_at`, an unsigned copy of
   the statement's timestamp. Editing the records' times to the same
   minute made the chain look instantaneous, and a chain with no span
   passes any policy, with or without anchors.

Separately, the gate ran only in the default text output. `--format json`,
which is what CI consumes, and `--full` never applied it and exited 0.

## Scope

- The false pass was local. Packages and bundles never carried anchors,
  so a counterparty verifying a `.treeship` package saw no anchoring claim
  at all, true or false. The exposure was to the operator's own
  `verify`, and to anything trusting it, such as a CI job using
  `--max-unwitnessed`.
- Signature verification, chain linkage and every other verdict were
  unaffected.
- The hub never stored a false anchor. It stored none.

## Fixed in

`0.31.9`.

**The hub submits a `dsse` entry.** Rekor's dsse type verifies each
signature over the PAE bytes, which is how Treeship signs. The hub
re-encodes payload and signatures as padded standard base64, submits the
dock's ship key as a PEM verifier, and keeps only signatures that verify
under that key. An artifact signed only by an agent key is reported as
skipped with a reason. It is no longer silently unanchored.

**The outcome is never silent.** The hub stores and returns
`rekor.status` (`anchored`, `failed` or `skipped`) with a reason, and
when anchored, the full Rekor log entry: body, integrated time, signed
entry timestamp, inclusion proof and signed checkpoint. Re-pushing an
artifact that never got anchored retries it, which is how existing
artifacts are backfilled. `hub push` prints what happened, and verifies
a returned proof before calling it anchored.

**An anchor counts only if its proof verifies offline.** `verify` now
checks every stapled Rekor entry against a trusted log key:

1. The entry's `logID` is the SHA-256 of a trusted log key.
2. Rekor's signed entry timestamp verifies over
   `{body, integratedTime, logID, logIndex}`.
3. The RFC 6962 inclusion proof leads from the entry to a root that a
   checkpoint signed by the same key commits to.
4. The entry is a dsse entry for this artifact: its payload hash is the
   SHA-256 of this artifact's payload, and it lists one of this
   artifact's own signatures with a key that verifies it over PAE. A
   genuine Rekor entry for other bytes cannot be stapled on.

The witnessed time is Rekor's signed `integratedTime`. `observed_at` is
kept for display and never counts. Anchors without a proof, including
every anchor recorded before this fix, are reported as
`claimed but unverified` and do not count. A proof that fails is
reported by reason and does not count.

**Claimed times come from the signature.** Coverage reads each
statement's signed `timestamp`, not `Record.signed_at`.

**The gate runs in every output mode.** Text, `--format json` and
`--full` compute coverage once and apply `--max-unwitnessed` the same
way. JSON output gains an `anchoring` object with the coverage, a tally
(`verified`, `claimed_unverified`, `failed_attempts`, `rejected`) and
the gate result.

**The proofs travel.** `session close` writes each sealed artifact's
Rekor proofs to `anchors/<id>.json` in the package, and `package verify`
checks them in an `anchoring` row. A proof that does not hold, or is for
another artifact, fails the row. A proof from a log the reader has not
pinned is a warning. A package with no proofs gets no row, so no existing
verdict changes. `bundle export` carries proofs the same way, and
`bundle import` merges them with anchors the local store already had.

**A checkpoint's caller-supplied `rekor_index` is ignored.** The hub
stored it and served it back verbatim, so any dock could attach an
arbitrary index to its checkpoint. It is null until the hub anchors
checkpoints itself.

**Rekor is its own trust root.** The Sigstore public-good log key is
built in. `treeship trust add <label> @rekor.pub --kind transparency_log`
pins a different log, such as a private Rekor, and replaces the
built-in key rather than adding to it.

## What a verifier should do

- Treat any `--max-unwitnessed` pass from `0.31.8` or earlier as
  unproven. Re-run it with the fixed release. Expect most chains to
  report `UNWITNESSED`: no genuine anchor existed before this fix.
- Read `anchoring.tally.rejected` in JSON output. A non-empty list means
  a record carries a proof that does not verify. That is either an
  edited record, a proof stapled onto the wrong artifact, or a log you
  have not pinned.

## What a producer should do

- Upgrade the CLI. Pushes against the fixed hub record a verifiable
  proof.
- Re-push artifacts that matter. The hub retries any artifact that has
  no Rekor entry.
- Know what goes public. A Rekor dsse entry publishes the payload's
  SHA-256, the signature and the ship's public key. It does not publish
  the payload. Per-artifact anchoring reveals how often a ship pushes.
  Anchoring checkpoint roots instead is planned.

## Reproduction

`packages/cli/tests/anchoring_forgery_cli.rs` builds eight-hour chains
signed by a real workspace key and plants what an editing operator
would: sixteen anchors with chosen times, a real Rekor entry for a
different artifact, and records whose times are compressed. Its six
attack tests were run against the 0.31.8 `verify`: all six fail there
and pass on the fix. A seventh checks that a passing policy is reported
as passed rather than as absent. `packages/core/tests/package_anchors.rs`
covers packages carrying proofs. The Rekor verifier's vectors are real
entries: one Treeship-format entry anchored in Sigstore's staging log by
the fixed hub, and one unrelated production entry
(`packages/core/tests/fixtures/rekor/`, provenance in each file).
`packages/hub/internal/rekor` holds the hub-side tests, including an
opt-in live submission to staging (`TREESHIP_REKOR_LIVE=1`).

## Not fixed here

- Per-artifact anchoring covers only what is pushed, and proves
  existence by push time, not creation time. Anchoring checkpoint roots
  at session close and periodically is the next step.
- Rekor v2 drops `integratedTime` in favour of RFC 3161 timestamp
  tokens. The verdict records its time source (`rekor-v1-integrated-time`)
  so that migration stays visible.
- Omission is still detectable only for committed sets.
