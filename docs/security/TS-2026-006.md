## Summary

Treeship through 0.31.12 could sign or accept actions that its own rules said it should refuse. A hub accepted a device-code approval that presented only the device code.

On the CLI and `treeship-core`:

- A project outside the home directory could have its session state taken from an ancestor `.treeship` directory, including one the operator did not create.
- A single-use approval could authorize a different action when the same idempotency key was presented again, and verification did not always notice that a use was already bound to another action.
- `treeship wrap` did not honor a project rule that required approval before running a command.
- A self-supplied effect readback was treated as independent evidence, so an effect could be graded verified.
- An expired key could still sign. A revoked grant could still sign. An out-of-scope action was signed and only warned. A key whose capability card was revoked for compromise could still sign and be graded proven.
- A halted actor could still attest and wrap.

On the hub, the device-code approval endpoint completed an attach from the device code alone. 0.31.13 also requires the user code shown to the operator.

## Fix

- Session discovery stops at the git root and the home directory, and it uses a discovered project config only when that file is owned by the operator and not group- or world-writable.
- An idempotency key is reused only for the same actor, action, and subject. A journal use vouches only for the action it names.
- `wrap` honors `require_approval` and does not start the command until an approval exists.
- A self-supplied readback is not independent evidence.
- `signer` refuses an expired key. A revoked grant, an out-of-scope action, and a revoked capability card cannot sign. `--record-violation` is the explicit way to record an out-of-scope attempt.
- A halted actor cannot attest or wrap.
- Device-code approval requires the user code in addition to the device code.
- A self-hosted hub does not anchor to public Rekor unless `TREESHIP_REKOR_URL` is set.

## Recommendation

1. Upgrade to 0.31.13: the CLI, `treeship-core`, `@treeship/verify`, `@treeship/sdk`, and `@treeship/core-wasm`.
2. **If you run your own hub, upgrade it to 0.31.13.** The device-code check is in the hub. `api.treeship.dev` was still on 0.31.12 when this advisory was published.
