# Telemetry

Treeship is local-first. `init`, `attest`, `wrap`, `verify` and `session` never send your work anywhere, and receipts leave your machine only when you publish them; the one network call they make is the ping this page describes. That also made the project blind to its own adoption: registry download counts are mirror and CI traffic, and the hub only sees the machines that choose to attach a dock.

So the CLI sends one small, anonymous ping. This page is the complete description of it.

## What is sent

One JSON object, seven fields, nothing else:

```json
{
  "schema": "treeship.telemetry.v1",
  "install_id": "ins_9f2c1a4be0d34c7f8a1b2c3d4e5f6071",
  "event": "install",
  "cli_version": "0.32.0",
  "os": "macos",
  "arch": "aarch64",
  "harness": "claude-code"
}
```

| Field | Values | Purpose |
|---|---|---|
| `install_id` | `ins_` + 32 hex characters | 16 random bytes generated by the CLI on first run and stored in `~/.treeship/telemetry.json`. Not a key, not the ship id, not a dock id, not derived from anything on the machine. It lets the hub count machines without knowing which. |
| `event` | `install`, `heartbeat` | `install` once, when the state file is created. `heartbeat` at most once every seven days, on whatever command runs next. |
| `cli_version` | semver | Which releases are actually in use. |
| `os` | `macos`, `linux`, `windows`, `other` | |
| `arch` | `x86_64`, `aarch64`, `other` | |
| `harness` | `claude-code`, `codex`, `cursor`, `unknown` | Which agent harness is driving the CLI, read from the environment variables those harnesses set. Anything unrecognised is `unknown`, never the raw value. |

Never sent: paths, hostnames, usernames, project names, command lines, receipts, artifacts, keys, dock ids, or anything typed at a prompt. The hub does not store the request's IP address or user agent.

`treeship telemetry status` prints the exact payload the CLI would send from your machine.

## When it is sent

- The first time any `treeship` command runs on a machine: `install`.
- At most once every seven days after that, on the next command: `heartbeat`.
- Never in CI (`CI` set to anything), never from a debug build unless `TREESHIP_TELEMETRY_ENDPOINT` is set, and never when any off switch below is on.

A send waits at most two seconds on first run and one second for a heartbeat, and its result is ignored: a hub that is down or a network that is blocked cannot fail or slow a command beyond that.

## Turning it off

Any one of these disables it:

```bash
treeship telemetry disable          # persisted in ~/.treeship/telemetry.json
export DO_NOT_TRACK=1               # the cross-tool convention
export TREESHIP_NO_TELEMETRY=1
```

`treeship telemetry enable` turns it back on. `treeship init` prints the state and the off switch at the end of its output, so nobody finds out about this page after the fact.

## What the hub does with it

`POST /v1/telemetry` on the hub accepts only the field set above. Unknown fields, values outside the allowlists, bodies over 2 KiB, or a second ping from the same id within twenty hours are rejected or dropped, and the response never echoes what was sent.

Storage:

- `telemetry_installs`: one row per install id with first-seen and last-seen times. Kept forever.
- `telemetry_events`: one row per accepted ping. Purged after 90 days.
- `telemetry_daily`: one row per UTC day with the counts. Kept forever.

The rollup is what makes the purge safe: the numbers outlive the rows they were computed from.

## What is published

The public [`/v1/stats`](https://api.treeship.dev/v1/stats) endpoint gains an `installs` block: total installs, new and active over 7 and 30 days, and breakdowns by version, harness and OS. Counts only, never ids. It carries its own `basis` string, because these numbers are a floor: machines that opted out are not in them.

## Why opt-out

An opt-in ping measures the people who read this page, which is not the population. An opt-out one measures everyone who did not object, which is closer, and the cost of being counted is one random number and five short strings. The switches above are honoured everywhere, including `DO_NOT_TRACK`, which you may already have set for other tools.
