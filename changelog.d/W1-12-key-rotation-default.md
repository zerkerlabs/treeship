- **`keys rotate` moves the default everywhere.** The keystore promoted the successor but `hub attach`, `prove` and the dashboard read the default from `config.json`, which still named the predecessor; a hub attached after a rotation was bound to a key that stopped being valid when the grace window closed. The keystore manifest is now the one source of truth and every reader uses it; nothing writes `config.json` on rotation (a first fix did, and flattened a project stub onto itself, breaking the ship). Rotations are serialised, so two at once form one chain instead of two successors for one key. `config::save` follows a project stub to the config it extends and writes atomically. `hub attach` records `created_at` as an RFC 3339 timestamp instead of `"<epoch>Z"`. (0.31.9 full test, CLI-9.)
