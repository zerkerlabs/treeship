- **One JSON document on stdout, everywhere.** `--format json add` printed one success document per detected harness; it now prints one document listing `configured`, `skipped`, `failed`, `detected` and `treeship_md`, and answers as one document when nothing is detected or none of the requested agents are. `attest action|action --v2|endorse --out -` wrote the DSSE envelope with a bare print before the result; in JSON mode the envelope is the `envelope` field of the result. `session report` with no hub attached put a report carrying `error` on stdout and exited nonzero; it is an error on stderr now, with `--no-upload` named for the local verdict. The JSON contract test no longer skips `add`.
- **`checkpoint --publish` reports a failed publish.** In JSON mode the sealed checkpoint is printed with `publish: {status: failed, ok: false, error}` and the command exits nonzero, so a retry does not seal a second checkpoint for nothing. The consistency-proof skip reasons are split: an empty previous tree, a previous checkpoint larger than this one, and a checkpoint covering more leaves than the store holds each say so, instead of every case reading "not a prefix".
- **`wrap` exit codes match the shell.** A child ended by a signal exits `128 + signal` (it exited 255 from a `-1`) and the JSON output carries `signal`; a command that cannot be started exits `127` with nothing signed. The wrap page documents that the propagated code can coincide with wrap's own.
- **The shell hook's upward walk stops at the home directory.** A `.treeship/config.yaml` above `$HOME` is not used.
- **Test hygiene.** Every CLI end-to-end test clears `TREESHIP_CONFIG`, so the suite passes with the variable exported in the developer's shell.
