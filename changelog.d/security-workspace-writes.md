- **Workspace writes no longer follow links.** Every file Treeship writes under a workspace, a keystore, a store or a session, and every file it writes where the user asked (`--out`, a package, a proof in the working directory), is created fresh and renamed into place, never through a symbolic link at the path or on the way to it, never into a file that has another name (a hard link), and temporary files are created exclusively under random names. A workspace, keystore or store directory that is itself a link, or sits below one, is refused with a message saying how to point `--config` at the real path. Files in the user's own home (a shell rc file, trust roots, saved templates) follow the user's own link and are written at its target, keeping its mode. A project config found by walking up from the current directory may keep its keystore and artifact store only inside its own `.treeship`; a config that points elsewhere is honoured when named with `--config` or `TREESHIP_CONFIG`.
