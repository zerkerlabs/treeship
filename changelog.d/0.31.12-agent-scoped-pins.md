- **Breaking: `agent_cert` pins carry an agent scope, and a pin without one no longer binds a card.** `treeship trust add … --kind agent_cert --agent agent://<name>` records which agent a key is pinned as; `agent register --own-key` writes it, and the pin lines from `keys export --agent <uri>` and `onboard` carry it. A `--kind agent_cert` line from an earlier release (no `--agent`) still lets that key's artifacts verify and import, but `resolve`, `verify-capability` and `verify-presentation` now grade such a card asserted and print the re-pin command, `treeship trust add <key_id> <pubkey> --kind agent_cert --agent <uri> --replace --yes`; a pin whose label is the bare agent name `agent register` wrote keeps binding. Changing a pin's agent needs `--replace`; pinning one public key as two agents warns.
- **Capability cards are judged on the keys that verified them.** A card is key-bound only when its own key is among the signatures that verified and that key's pin names the card's agent; `resolve` picks the current card among the agent's key-bound cards, newest first, locally and with `--hub`, and the hub serves every revocation that names a card rather than one. The verdicts from `resolve`, `verify-capability`, `verify-presentation` and the SDKs carry `key_bound_reason` (`pin_unscoped`, `pin_scoped_to_other`, `not_pinned`, `key_not_verified`, `agent_uri_invalid`) for scripts. A revocation with reason `compromised` applies to every card of that key; `trust remove` remains the definitive answer to a compromised key.
