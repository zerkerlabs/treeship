- **`sync-changelog.mjs --check` no longer compares the Unreleased section.** It's exactly whatever `changelog.d/` fragments happen to be on `main` right now, a moving target every fragment-adding PR shares -- comparing it meant landing any one PR's fragment made every other open PR's already-correct branch fail the check, the same per-PR churn `changelog.d/` was built to remove. `--check` now strips `## Unreleased` (heading through the next `## ` heading) from both sides before comparing; released sections, the actual content responsible for the drift this check exists to catch, are still compared in full. Verified both properties: adding an unrelated fragment no longer fails the check, and a genuine edit to an already-released section still does.
