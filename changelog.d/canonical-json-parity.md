- **One canonical-JSON encoder instead of three.** `disclosure`, `merkle::checkpoint` and `statements::invitation` each carried their own copy of `canonical_json_string`, and each one feeds a digest that ends up inside a signed artifact. They were the same algorithm written three times, with nothing stopping one from drifting and silently changing a digest that older records were signed over. They now share `core::canonical`, whose tests pin the encoding byte for byte, pin that empty members and nulls participate rather than being stripped, and pin that keys sort in code-point order. The module documents what this encoding is and is not: RFC 8785 sorts keys by UTF-16 code unit and prints numbers by ECMAScript rules, so adopting it means a new, additive digest, never a change to this one. No behaviour changes.
