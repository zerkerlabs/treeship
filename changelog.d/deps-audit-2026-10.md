- **The dependency audits pass again, and the one advisory that reached the shipped binary was fixed rather than ignored.** `cargo audit` had accumulated twelve vulnerabilities since the last sweep, because an advisory database moves whether or not the code does. Eleven of them -- five in `quinn-proto`, four in `rustls`, one in `rustls-webpki`, one in `crypto-bigint` through a second path -- were already fixed upstream and cleared by updating the lockfile. The twelfth, RUSTSEC-2026-0387 (timing variability in operations meant to be constant-time), reached `treeship-cli` through `p256` → `elliptic-curve` → `crypto-bigint 0.5.5`, which `.cargo/audit.toml` says plainly is not a candidate for the ignore list: fix it or hold the release. Fixing it meant `p256 0.13 → 0.14`, whose `crypto-bigint 0.7` has the constant-time work. The API moved in three places -- `to_encoded_point` became `to_sec1_point`, and `SigningKey::random` became the `Generate` trait, whose `generate()` draws from the system CSPRNG through the crate's own getrandom path rather than this crate reaching for a second, differently-versioned `OsRng`. The encodings are unchanged, which the Verifiable Intent interop fixtures pin byte-for-byte and which they still pass.
- **The keystore stopped using deprecated `generic-array` constructors.** The newer `sha2` deprecates `GenericArray::from_slice` and `as_slice`, and CI runs clippy with `-D warnings`, so eleven call sites in the AES-256-GCM keystore and the approval-use digests had to move. The key is built from the 32-byte array directly and the nonce through `try_into`, which turns the length guarantee the framing check already established into an assertion rather than an assumption. The bytes are identical, and rather than take that on faith it was checked across binaries: a keystore written by the previous release decrypts, signs and verifies under this one.
