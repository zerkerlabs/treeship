- **The shell hook records into the project whose session is open.** `treeship hook post` (installed by `treeship install` into the shell) used the store an exported `TREESHIP_CONFIG` named, not the project's `.treeship/config.json` beside the `config.yaml` it had found, so a session started with `--config` in the project and the hook's receipts could end up in different stores. For the shell hook only, the precedence is now: an explicit `--config`, then the project's own config when a session is active in that project, then `TREESHIP_CONFIG`, then discovery. The project config is opened as a discovered config, so a cloned repository's `config.json` gets every discovery check (stores inside its own `.treeship`, no `extends` outside the home, no linked `.treeship`) before any key is used.
- **The lockfile check also compares the package's own version.** A `package-lock.json` whose root version lags `package.json` (the OpenClaw plugin's read 0.10.3 at 0.31.10) fails `scripts/check-lockfile-sync.py`; the plugin's lockfile is refreshed, `scripts/lockfile-pin.py` stamps those fields at release time, and the plugin is in `release.sh`'s lockfile lists.
- **Clippy runs on wasm32 in CI (PKG-3).** `std::fs::File` has no `Drop` on that target, so an explicit `drop(lock_file)` in the keystore migration failed the lint there; the handle is bound to the function's scope instead, and the feature-matrix job lints core-wasm on wasm32 with warnings denied.
