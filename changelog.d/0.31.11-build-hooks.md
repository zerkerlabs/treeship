- **The Claude Code hook records into the project's own workspace.** `hook post` used the store an exported `TREESHIP_CONFIG` named, not the `.treeship/config.json` beside the `config.yaml` it had found, so a session started with `--config` in the project and the hook's receipts could end up in different stores. The project config now wins over the environment; an explicit `--config` still wins over both.
- **The lockfile check also compares the package's own version.** A `package-lock.json` whose root version lags `package.json` (the OpenClaw plugin's read 0.10.3 at 0.31.10) fails `scripts/check-lockfile-sync.py`; the plugin's lockfile is refreshed.
- **Clippy runs on wasm32 in CI (PKG-3).** `std::fs::File` has no `Drop` on that target, so an explicit `drop(lock_file)` in the keystore migration failed the lint there; the handle is bound to the function's scope instead, and the feature-matrix job lints core-wasm on wasm32 with warnings denied.
