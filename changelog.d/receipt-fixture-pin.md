- **The dogfood's verifier pin says why it exists.** `receipts.yml` pinned `treeship-version: "0.31.5"` with no reason given, and that pin was holding a failure out of sight: the committed fixture was sealed before 0.31.10 by an agent holding its own key, so its close record names no record key, and the `receipt_binding` check added in 0.31.10 fails it under every newer release. It passes under `--structural`, but that path does not check signatures at all, so using it here would turn the dogfood into a check that proves nothing about the signing it exists to prove. The pin now carries the reason, the consequence of raising it, and the condition for removing it: reseal the fixture with a current release under the ship key pinned in `receipts/trust_roots.json`, which only the maintainer holds.
