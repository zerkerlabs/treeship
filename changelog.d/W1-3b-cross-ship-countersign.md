- **A room works across two machines, and the host is the single-use gate.** A joiner on another machine could not be countersigned: `session countersign` required the invitation's nonce to have been consumed in the host's own journal by `session join`, which only happens when both run on one machine. The same check let a host countersign any further pending envelope for an invitation once one join had consumed it. Now `session join --out <file>` writes the pending envelope for the host, and `session countersign --pending <file>` countersigns it: the file must hold exactly one pending envelope whose joining-agent signature verifies, its id is re-derived from its bytes, and the invitation it redeems must be one this host issued. Across machines `--challenge` and `--challenge-response` are required; on one machine they stay optional for now, with a notice that they become mandatory in 0.32. Countersign itself enforces single use: it reserves the use in the host's journal before signing, up to the invitation's `max_uses`, and never releases it, so a second countersign for a single-use invitation is refused wherever the join ran. Audit 2026-09-25, CLI-3 (W1-3b).
- **A countersign checks that the join challenge is fresh and the session is still open.** The challenge must be no older than ten minutes (`TREESHIP_JOIN_CHALLENGE_WINDOW_SECS`), and the joiner's answer must be signed between the challenge and now; `--pending` also requires `--challenge-issued-at`. Countersign refuses an invitation whose session is not the one open on this ship. Every check runs before the use is reserved, so a refused countersign never uses up the invitation, and a busy journal says to retry instead of claiming the invitation was already used.
