- **Which workspace a command uses is never a guess.** A project's `.treeship/config.json` stub records the account's global config by absolute path, so under a different `HOME` (a test harness, a container) with no `--config` or `TREESHIP_CONFIG`, discovery still routed to the original account's keystore and signed into its store. A discovered stub that extends a config outside the current `HOME` is now refused with the two ways to say which workspace you mean; an explicit `--config` or `TREESHIP_CONFIG` always wins over discovery (a test pins it); and discovery never climbs above `HOME`. `status` and `doctor` already print the resolved source.
