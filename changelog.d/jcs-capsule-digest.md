- **RFC 8785 canonical JSON, beside the encoding Treeship signs.** `core::jcs` adds the JSON Canonicalization Scheme and `capsule_digest`, the lowercase-hex SHA-256 over `UTF8(JCS(value))` that the Agent Action Capsule profile specifies, so Treeship records can be committed to in a form other implementations recognise. It is additive and nothing signs with it: JCS orders object keys by UTF-16 code unit where Treeship's signing encoding orders by code point, and the two invert above the Basic Multilingual Plane, so changing the existing digest would break verification for every record already in the field. A test pins that divergence from both sides. Floating-point values are refused with an explicit error rather than converted, because the capsule profile forbids them in digest-bearing material and a producer that invents a mapping emits digests nobody else can reproduce; integers outside the IEEE-754 safe range are refused for the same reason. Empty members and nulls participate, as the profile requires, rather than being stripped the way the withdrawn `jcs-n` construction does.
