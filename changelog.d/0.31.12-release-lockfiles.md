- **Lockfiles are refreshed by the release workflow.** The npm lockfiles at a tag name the previous release, because `release.sh prepare` cannot hash tarballs that do not exist yet; the refresh after publish was a manual step, and v0.31.10 and v0.31.11 both left main unbuildable for JS for hours. The release workflow now waits for the published packages, runs `release.sh refresh-lockfiles` and opens the lockfile PR itself. `RELEASING.md` documents the order of operations, why `npm ci` at a tag commit cannot work for the in-repo JS packages, and the hub deploy. (0.31.11 re-test, N-3.)
- **Hub deploys carry their commit.** `railway up` uploads have no `.git`, so `/v1/version` reported `commit: unknown`. `scripts/hub-deploy.sh` sets `HUB_VERSION`, `HUB_COMMIT` and `HUB_BUILT_AT` on the Railway service (the Dockerfile takes them as build args) and then uploads. (N-34.)
