- **The hub says which build it is, and checkpoints can publish on a schedule.** `GET /v1/version` (alias `/version`) on the hub returns the version, commit, build time and Go runtime from the build, "dev"/"unknown" when unset; `/health` joins `/healthz`. The public hub had no version endpoint, so nobody could tell from outside whether a fix was deployed. `GET /v1/merkle/checkpoint/latest` adds `age_seconds`, computed at read time, for a monitor to alert on. On the CLI, `treeship checkpoint --publish` seals and pushes in one command and exits nonzero if the push fails; an opt-in `checkpoint.every` in config.yaml makes the daemon seal and publish on that interval, logging each publish, and `doctor` reports the cadence only as it actually runs. A checkpoint is signed by the publishing ship; the hub stores it and signs nothing. The hub half takes effect when it is next deployed. (0.31.9 full test, WEB-4.)
