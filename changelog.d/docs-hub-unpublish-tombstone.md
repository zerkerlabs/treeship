- **Docs and the claims registry catch up to `treeship hub unpublish` (#533).** `treeship hub unpublish` had no CLI reference page section -- `docs/api/receipt-delete.mdx` already linked to `/docs/cli/hub` for it, but the page never documented the command. Added a full `## treeship hub unpublish` section (usage, options, the permanence callout) and its row in the commands table. `docs/claims.yml`'s `hub-storage-write-once` claim said the Hub's storage was write-once with no exceptions; it now also describes the one real exception, the publisher's own one-shot tombstone (`DELETE /v1/receipt/{session_id}`, verified against `db.TombstoneSession` and `InsertSessionWriteOnce`'s explicit `"tombstoned"` guard, which refuses to ever refill a taken-down session id). Six other pages that explain publishing (`concepts/session-receipts.mdx`, `cli/session.mdx`, `cli/package.mdx`, `api/receipt-put.mdx`, `guides/quickstart.mdx`, `sdk/python.mdx`) called the receipt URL "permanent" or said it "never expires" -- true before this release, no longer since a publisher can take it down -- reworded to say the URL stays up until unpublished, with a link to the command. `treeship session report`'s own success hint (`packages/cli/src/commands/session.rs`) had the identical overclaim baked into the CLI itself ("they never expire and need no auth"); fixed at the source, not just in docs, to "they need no auth and stay up until you unpublish them."
