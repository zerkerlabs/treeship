- **A pull request now carries its own verdict.** `verify-receipts` verified every sealed package and then wrote the result to a step summary behind a click into the Actions tab, which is the same place nobody looks, so a reviewer read an agent's own description of its work and nothing else. The action now posts a verdict comment on the pull request and edits that comment in place on later runs: a monospace block saying whether the trace verified and over how many receipts, what the agent did in counts, and, last, what was *not* captured, with the offline verify command. Lines whose evidence is not in the package, judgements and signed approvals, are omitted rather than invented. Commenting needs `pull-requests: write`; a fork pull request gets a read-only token, where the comment is skipped with a warning and the verdict still stands in the log, the annotations and the summary. A comment never decides whether the check passes.
