- **`daemon status` no longer kills the daemon, and `daemon start` backgrounds.** The pid file holds `<pid> <start epoch>`, but the reader parsed the whole line as one number, so every read failed: `status` reported "stopped", deleted the file, and the daemon (which exits when its pid file disappears) died of a status check; `stop` then said "not running". The reader takes the pid, a pid file is removed only when it names a process that is gone, and a file that does not parse is reported and left alone. `daemon start` without `--foreground` now starts a detached child and returns with its pid; it used to run in the foreground and print "tip: run with &". (0.31.9 full test, CLI-8.)
