- **Share URLs come from the hub you pushed to.** After `hub push` or `session report` to a self-hosted hub, the CLI printed `https://treeship.dev/verify/…` and `/receipt/…` addresses that held nothing, because the hub hard-coded them in its replies. The hub now builds them in order: `TREESHIP_PUBLIC_URL` when set (a self-hoster with a page site); today's treeship.dev pages when the request reached a treeship.dev host, checked on `X-Forwarded-Host` then `Host`, so the public hub behind its proxy needs no configuration; otherwise its own API URLs (`<hub>/v1/receipt/<id>`, `<hub>/v1/artifacts/<id>`), which `treeship verify <url>` accepts. The CLI prints what the hub returns and, when a hub returns no URL, derives one from the attached endpoint instead of www.treeship.dev; `session report` no longer prints preview and package page links for a hub that has no pages, and `hub push` no longer suggests `treeship open`, a command that does not exist. The hub half takes effect on the public hub when it is next deployed. (0.31.9 full test, CLI-12.)
