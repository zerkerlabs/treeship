- **A published receipt can be taken down.** `treeship hub unpublish <session_id>` sends a DPoP-signed `DELETE /v1/receipt/{session_id}`; only the dock that published the receipt may call it. The hub removes the receipt body for good and keeps only the id, the dock and the takedown time; the receipt URL answers `410 Gone` with a short reason from then on, never the old bytes, and the session id cannot be re-uploaded. Local copies are untouched.
- **Session receipts carry no absolute home paths.** Files under `$HOME` are recorded as `~/...` when the receipt is composed, so the close record signs the redacted form and file digests are unchanged. A published receipt had carried over a thousand local `/Users/<name>/...` paths.
- **Hub responses carry `Vary: Origin`**, so a shared cache never serves one origin's CORS header to another on receipts cached as immutable; `HEAD` is answered on every `GET` route instead of 405; `DELETE` and `HEAD` are in the allowed methods.
- **`/v1/version` reports a real version on Railway.** The Dockerfile's build args default from `RAILWAY_GIT_COMMIT_SHA`, and an unset version falls back to the hub's own `Release` constant, which the release script stamps, instead of `dev`.
- **The shell hook ignores stale state.** `hook post` for a command other than the one `hook pre` matched drops the leftover state and records nothing, instead of attributing the old command to the new run.
