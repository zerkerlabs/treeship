- **A published receipt can be taken down.** `treeship hub unpublish <session_id>` sends a DPoP-signed `DELETE /v1/receipt/{session_id}`; only the dock that published the receipt may call it. The hub removes the receipt body for good, along with the session's name, timing and counts, and keeps only the id, the dock and the takedown time; the receipt URL answers `410 Gone` with a short reason from then on, never the old bytes, and the session id cannot be re-uploaded. Local copies are untouched, and a copy a browser or proxy cached while the receipt was public can persist for up to 24 hours. Taken-down receipts are left out of `/v1/stats` session counts.
- **Session receipts carry no absolute home paths.** Files under `$HOME` are recorded as `~/...` when the receipt is composed, so the close record signs the redacted form and file digests are unchanged. The same substitution runs over command lines (`treeship wrap`, shell-tool events), `file://` URLs, network destinations, agent notes, and the process names and timeline summaries built from them, wherever the home directory appears at a path boundary; the resolved form of `$HOME` is redacted along with the literal one. `session close --summary` is the operator's own text and is published as written. A published receipt had carried over a thousand local `/Users/<name>/...` paths.
- **Hub responses carry `Vary: Origin`**, so a shared cache never serves one origin's CORS header to another on receipts cached with `Cache-Control: immutable`; `HEAD` is answered on every `GET` route instead of 405; `DELETE` and `HEAD` are in the allowed methods.
- **`/v1/version` reports a real version on Railway.** The Dockerfile's build args default from `RAILWAY_GIT_COMMIT_SHA`, and an unset version falls back to the hub's own `Release` constant, which the release script stamps, instead of `dev`.
- **The shell hook ignores stale state.** The installed zsh, bash and fish hooks now pass the finished command to `hook post`; state left by a `hook pre` for a different command is dropped and nothing is recorded, instead of attributing the old command to the new run. In bash the whole typed line is taken from history once per prompt when history just recorded it, so `git commit -m x && echo ok` is recorded once and an empty Enter records nothing; a line history did not record is taken from `BASH_COMMAND`, so nothing is ever signed for a command that did not run. The snippets are quiet under `setopt nounset`, the hooks run with `--quiet` so a matched command prints nothing into the prompt, and hook diagnostics go to stderr. `treeship uninstall` gives the file back byte for byte. A hook from an earlier release passes no command; there, state older than 24 hours is dropped. `treeship install` replaces an older hook block with the current one and changes nothing outside its marker lines.
