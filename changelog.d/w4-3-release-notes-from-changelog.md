- **GitHub Releases now lead with the actual CHANGELOG section (W4-3).** `release.yml`'s `release` job used only `generate_release_notes: true`, GitHub's compare-commits diff -- no editorial content, and not very useful against this repo's squash-merge history. It now extracts the tagged version's own `## X.Y.Z (date)` section from `CHANGELOG.md` (guaranteed present by tag time, since `scripts/release.sh prepare` runs `changelog.py assemble` before `tag` ever runs) and passes it as the release body; `generate_release_notes` stays on, so GitHub still appends its auto-generated section below it.
