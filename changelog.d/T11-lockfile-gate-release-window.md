- **A release no longer tags a red main.** The lockfile check (`scripts/check-lockfile-sync.py`) failed on `main` between the version bump merging and the packages reaching npm, because the installed lockfile entries could not yet name a version that had no tarball, so every release was tagged on a failing commit. An installed entry that lags the release in flight (the version in `packages/core/Cargo.toml`) is now a warning while that exact version is not on the registry, and fails again the moment it is published, which is what forces `scripts/release.sh refresh-lockfiles`. The declared-range half of the check, the release-branch window, and the behaviour when the registry cannot be reached are unchanged. The gate has unit tests with the registry lookup stubbed.
