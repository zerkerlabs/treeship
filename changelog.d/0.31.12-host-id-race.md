- **Concurrent first sessions agree on one host id.** The first session on an install without `~/.treeship/host_id` mints the id with an exclusive create, and a session starting at the same moment reads it back. The file was created before its bytes were written, so a reader in that window found it empty and fell back to `host_unknown` for its events. The id is now written to a temp file beside it and published by linking that file to `host_id`, which fails when the name is taken and never exposes an unwritten file; where the filesystem has no hard links, a reader that finds the file still shorter than an id waits briefly and reads again. (0.31.11 re-test, N-41 follow-up.)
