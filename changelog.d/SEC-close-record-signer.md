- **The close record is bound to its session, not to the reader's trust store; `verified` needs rows that passed.** `package verify` took the close record's key from the package's own `keys.json` and never tied it to the session, so a package whose `receipt.json` was rewritten and re-bound by a fresh record, under an added key or under any other key the reader had pinned, verified, `--strict` included. The record must now be a `session.v1` receipt statement naming, as its subject, the sealed `session.close` action of this session, and be signed by that close's signer or by the record key the signed close names. `session close` now names the agent's record key in `session.close` when an agent with its own key (`agent register --own-key`) signs the record, so pinning the ship key is enough. **Behaviour change: a package closed before this release by an agent with its own key names no record key and fails `receipt_binding`; read it with `--structural`.** When any signing key in a package is pinned (or this ship's own), every other signer must be too, or be the record key a trusted close names: a trusted package carrying an artifact signed by a key nobody vouched for fails `signer_trust` instead of warning. Separately, the verdict came from the absence of failures, so a package sealing no artifacts and carrying no close record read `verified`: `verified` and `signatures-pass` now require a verified artifact signature, a passing `receipt_binding` and a `signer_trust` row, `structural-pass` requires a sealed set, and a missing close record fails whatever the package carries. The same rule drives `treeship verify <package>` (including its `--certificate` cross-check), `treeship dashboard` and `session report`.
- **A key id is a label, and no longer vouches on its own.** A package whose key id names a different public key than the root pinned under that id fails `key_id_collision` (a forger re-signing a victim's chain under the victim's id no longer reads as the victim's). `treeship trust add` refuses to re-point a pinned key id at a different key without `--replace`, and shows both fingerprints. Trust rows name the pinned root a key matched (label, kind, fingerprint), and pin hints show the key's fingerprint and leave out `--yes`, so a key copied from a package is confirmed before it is trusted. An action that consumes an approval must have its use record in the package's `approvals/` (`approval_evidence`), so deleting that directory can no longer hide the approval-use and replay checks. `treeship verify <package>` honours `--config`, and `session report`'s status is the package verdict (pass = verified, warn = signatures-pass, fail = failed), the same word the dashboard shows.
