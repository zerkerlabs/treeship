- **A close record signed by a key nobody pinned no longer vouches for a package, and `verified` needs rows that passed.** `package verify` took the close record's key from the package's own `keys.json` and never judged it, so a package whose `receipt.json` was rewritten and re-bound by a fresh record under an added key verified, `--strict` included. The record must now be a `session.v1` receipt statement; its key is judged with the artifact signers in `signer_trust`, and a record key that signed none of the sealed artifacts must be pinned here (or be this ship's own), or `receipt_binding` fails. **Behaviour change: a package closed by an agent with its own key (`agent register --own-key`) needs the agent key pinned as well as the ship key**; the failure prints the `treeship trust add` line. Separately, the verdict came from the absence of failures, so a package sealing no artifacts and carrying no close record read `verified`: `verified` and `signatures-pass` now require a verified artifact signature, a passing `receipt_binding` and a `signer_trust` row, `structural-pass` requires a sealed set, and a missing close record fails whatever the package carries (read it as structure with `--structural`). The same rule drives `treeship dashboard` and `session report`'s verification status.
