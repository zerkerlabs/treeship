- **Package verification is stricter about who closed a session and what a verdict requires.** Security fix; see the accompanying advisory. The close record must be the session's `session.v1` record, name the sealed `session.close`, and be signed by its signer or by the record key it names; `session close` now names an agent's own record key in `session.close`, so pinning the ship key is enough. **Behaviour change: a package closed before this release by an agent with its own key fails `receipt_binding` by default; read it with `--structural`.** `verified` and `signatures-pass` now require checks that passed (an artifact signature, `receipt_binding`, `signer_trust`), and `structural-pass` requires a sealed set. When any signing key is trusted, every other signer must be trusted or vouched for by the session's own signed records. Approval signers are judged in a new `approval_signer` row; approval use is checked against the approval's signed scope (`approval-use-limit`), and approval-consuming actions need their use records (`approval_evidence`). A key id that names a different key than the root pinned under it fails `key_id_collision`. `treeship verify <package>`, `treeship dashboard` and `session report` report the same verdict as `package verify`, and `verify <package>` honours `--config`.
- **`trust add` protects pinned key ids.** Pinning a different public key under an already-pinned key id needs `--replace` and shows both fingerprints; this ship's own key ids cannot be re-pointed at all. Pin hints show the key's fingerprint and leave out `--yes`, so a key copied from a package is confirmed before it is trusted.
- **Approvals carried with a package are checked like sealed ones.** An approval minted before the session, which the package carries in `approvals/grants` rather than in the sealed set, is verified against its signature and its signed use limit; two approvals that share one nonce fail. `package verify --structural` judges trust with this ship's own keys too, and `trust add` checks this ship's own key ids against the workspace `--config` names.
