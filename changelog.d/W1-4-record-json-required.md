- **A package without its close record fails `package verify`.** Nothing in a package says, under a signature, which release built it, so a package from before 0.31.4 and a later package with `record.json` deleted look the same. The verifier treated both as legacy and downgraded the `receipt_binding` check to a warning, so an edited package could still verify by default (see the advisory published with 0.31.10). Now a package that carries artifact envelopes (0.31.2 and later) but no close record fails `receipt_binding`, and the message says the sealed set is not under a signature. For a package you know 0.31.2 or 0.31.3 built (the only releases that wrote that shape), `--structural` reports what can still be checked, with verdict `structural-pass`, never `verified`. Packages from before 0.31.2 are unchanged. Audit 2026-09-25, CLI-4; the cases are T2 vectors.
