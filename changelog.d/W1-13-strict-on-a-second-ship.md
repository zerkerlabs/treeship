- **An honest approval or room package verifies under `--strict` on a second ship.** `--strict` failed every approval-bound and every room package on any machine but the producer's. The approval, the invitation, the participant and its liveness record are sealed unchained, and `chain_completeness` treated them as loose; and the producer's Approval Use Journal, which a second ship can never hold, was required. An unchained artifact that a signed reference inside the sealed set accounts for is now bound: an approval whose nonce a chained action consumes in its signed `approvalNonce`, a participant whose countersign verifies against its sealed invitation, that invitation, and the host's liveness record for that participant. The referencing signer must be authenticated here, so an attacker's own action cannot vouch for an approval it smuggled in; package order stays unproven, and the row says so. The local-journal check applies only where the package was produced (a sealed artifact verifies under one of this ship's keys); elsewhere a `local_journal` row says it is not applicable and what was checked instead, and `--strict` does not promote it.
